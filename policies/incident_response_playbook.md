# Incident Response Playbook for Insider Threat

## 1. Overview
This playbook defines the step-by-step process for responding to insider threat alerts generated by the InsiderLens detection platform. All actions must follow the Privacy-by-Design principles documented in the Acceptable Use Policy.

## 2. Alert Triage (First 30 Minutes)

### 2.1 Initial Assessment
- Review the alert in the InsiderLens dashboard using the pseudonymized user ID
- Check the risk score and severity classification (LOW/MEDIUM/HIGH/CRITICAL)
- Review evidence tags and the AI-generated explanation
- Check the kill-chain stage(s) identified

### 2.2 Context Gathering
- Review the user's baseline behavior comparison (Z-scores vs self and vs peer group)
- Check for correlated alerts or existing cases for this user
- Review the user's department and role context
- Check if the user is on a departing-employee or contractor watchlist

### 2.3 Priority Classification
| Severity | Response Time | Action |
|----------|--------------|--------|
| CRITICAL (Risk ≥ 85) | Immediate (< 15 min) | Escalate to Security Lead, consider containment |
| HIGH (Risk ≥ 65) | Within 1 hour | Detailed investigation, prepare identity reveal request |
| MEDIUM (Risk ≥ 40) | Within 4 hours | Monitor, gather more evidence |
| LOW (Risk ≥ 20) | Next business day | Add to watchlist, continue monitoring |

## 3. Investigation Procedures

### 3.1 Behavioral Analysis
1. Use the User Analysis page to review the daily outbound volume trends
2. Compare the user's activity pattern with their peer group (same department)
3. Check for unusual after-hours activity patterns
4. Review new destinations contacted by the user
5. Examine the hourly activity distribution for timing anomalies

### 3.2 Flow-Level Investigation
1. Review flagged flows in the Alerts & Cases page
2. Check destination categories (cloud storage, webmail, paste sites, unknown)
3. Analyze upload-to-download ratios for suspicious flows
4. Check for DNS tunneling indicators (high entropy, long queries)
5. Check for beaconing patterns (regular intervals, consistent payload sizes)

### 3.3 Using the AI Copilot
- Ask natural language questions about the user's behavior
- Compare the user with their peer group using questions like "Compare USER-XXX with the rest of their department"
- Ask "Why was USER-XXX flagged?" to get a narrative explanation
- Ask "Who else contacted that destination?" to find related activity

## 4. Identity Reveal Process

### 4.1 Prerequisites for De-anonymization
- User risk level must be HIGH or CRITICAL
- Written justification documenting the security concern
- Approval from a Security Lead or CISO

### 4.2 Reveal Request Steps
1. Navigate to the Privacy & Audit page in the dashboard
2. Select the pseudonymized User ID
3. Provide detailed written justification
4. Submit the reveal request
5. Wait for Security Lead approval
6. All reveal actions are logged in the immutable audit trail

## 5. Containment Actions

### 5.1 Available Containment Options (require manager approval)
- Temporary upload rate limiting for the user
- Block specific destination IPs/domains
- Increase monitoring sensitivity for the user
- Revoke access to sensitive file servers
- Disable VPN access for the user account

### 5.2 Containment Decision Matrix
| Kill-Chain Stage | Confidence | Recommended Action |
|-----------------|------------|-------------------|
| Exfiltration (Active) | High | Immediate containment + manager notification |
| Staging/Collection | High | Increased monitoring + manager notification |
| Reconnaissance | Medium | Continue monitoring, add to watchlist |
| Cover-up detected | High | Preserve evidence, escalate to CISO |

## 6. Incident Report Generation

### 6.1 One-Click Report
1. Navigate to the case in Alerts & Cases
2. Click "Download Incident Report"
3. The report includes: Executive Summary, User Profile, Timeline of Events, Evidence Summary, Kill-Chain Assessment, Risk Assessment, Recommended Actions, and Caveats

### 6.2 Report Distribution
- Reports are classified as CONFIDENTIAL by default
- Distribution limited to Security Team, CISO, and authorized management
- All report access is logged in the audit trail

## 7. Post-Incident Review

### 7.1 Analyst Feedback
- Label each alert as True Positive, False Positive, or Inconclusive
- Feedback is used to tune detection thresholds and reduce alert fatigue
- Document any new patterns or indicators discovered during investigation

### 7.2 Policy Updates
- Review if existing policies need updating based on the incident
- Update allowlists if legitimate business activities were flagged
- Add new threat patterns to detection rules if applicable

## 8. Escalation Contacts
| Role | Responsibility |
|------|---------------|
| Security Analyst | Initial triage and investigation |
| Security Lead | Approve identity reveals, review escalations |
| CISO | Approve containment, executive reporting |
| HR Manager | Employee context, formal action coordination |
| Legal Counsel | Privacy compliance, evidence handling |
